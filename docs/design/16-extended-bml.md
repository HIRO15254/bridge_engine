# 16. 拡張 BML リファレンス (`bridge-system` が受理する方言)

本書は、`crates/bridge-system` のコンパイラ (`COMPILE_REVISION` 9、`IR_FORMAT` 3) が受理する BML (Bridge Bidding Markup Language) の方言の、唯一の正本である。上流の BML (gpaulissen/bml の `bml.py` / `bss.py`) に、フェーズ 3〜4 で加えた拡張 (`#+KEY:` メタ、`{prio:N}` / `{w:X}` / `{stop}` 注釈、`X`/`XX`、`2S/3H`・`4D/H`、`n`・`c`・`j` のレベル、`(any)`/`(bid)`/`(suit)`、`#STOP`、`#ANYORDER`、スート長の比較、…) を含めて、新しいシステムファイルをソースを読まずに書けるように、コードから書き起こした。

- 設計の経緯と内部構造は `06-system.md` にある。本書と `06-system.md` が食い違うときは、コードと本書が正である (既知の食い違いは付録 B)。
- SAYC の実例は `systems/sayc/*.bml` (ルートは `sayc.bml`) にある。
- 本書の `bml` のコードブロックは、`crates/bridge-system/tests/bml_reference.rs` が全て抜き出してコンパイルする (§0.2)。本書の例は「動く」ことが試験で保証されている。

## 0. 読み方

### 0.1 表記

- 「上流」は gpaulissen/bml の Python 実装 (`bml.py` は HTML/LaTeX への変換器、`bss.py` はビディング表の展開器 (BSS 出力)) を指す。
- 「(拡張)」は上流に無い構文・意味、「(上流)」は上流と同じもの。
- 文法は EBNF で書く。`WS` は 1 個以上の空白 (半角スペース)、`WS0` は 0 個以上、`NL` は改行。完全な文法は §9。
- `Lint` の名前は `LintCode` の variant 名 (`IllegalCall` など) で書く。重大度は Error / Warning / Info。一覧は §8。
- 「我々」はシステムの持ち主のパートナーシップ、「相手」は反対側。

### 0.2 本書の例の試験

`crates/bridge-system/tests/bml_reference.rs` は、本書の各コードブロックを情報文字列で区別して扱う。

| 情報文字列 | 意味 |
| --- | --- |
| `bml` | 単独のファイル (`root.bml`) としてコンパイルし、Error の Lint が 0 件であること |
| `bml,should-lint` | 1 行目に `// expect-lint: <Code>` (列 0 の注釈なのでコンパイラは読み飛ばす) を書く。その Lint が出ること、それ以外の Error が出ないこと |
| `bml,file=<path>` | 内容を `<path>` という名前のファイルとして登録し (他のブロックの `#INCLUDE <path>` がこれを読む)、それ自身も `bml` と同じく検査する |

同じ試験は、`LintCode` の全 variant、全ての `#+KEY:`、説明文の語彙表 (`compile/desc/tokens.rs`、`clause.rs`、`recognition.rs` の語の表) の全ての語が本書に書かれていることも確かめる。コードに語や Lint を足したら、本書に足さないと試験が落ちる。

### 0.3 Lint の見方

コンパイルは決して全体としては失敗せず、問題を `Lint` の列として返す。自分のファイルの Lint を見るには、次のようにする (`Lint` の `Display` は `file:line: severity[Code]: message`。`file` は `#INCLUDE` 順のファイル番号で、0 がルート)。

```rust
use bridge_system::{CompileOptions, compile, lexer::FsLoader};

let path = "systems/mine/root.bml";
let text = std::fs::read_to_string(path)?;
let (ir, lints) = compile(path, &text, &FsLoader, &CompileOptions::default());
for lint in &lints {
    println!("{lint}");
}
```

## 1. 範囲と互換性

### 1.1 上流 BML との関係

本方言は、上流 BML 2 (README 2021-07、`bml.py` / `bss.py`) の **ビディング表の部分** の上位互換である。上流の正しいファイルは、次の例外を除き、本コンパイラで同じ展開になる (上流の `test/data/example{1..6}.bml` と期待出力 `.bss` を `tests/bss_oracle.rs` がオラクルとして照合している)。

- 本コンパイラが扱うのは入札の定義だけである。上流の文書機能 (見出し・リスト・段落のフォント記法 `/i/ *b* =mono=`、ディール図、4 列オークション表、パイプ表) は、段落として読み飛ばす (制約にも Lint にも影響しない)。
- `#HIDE` (上流: 表を BSS にだけ出す) は印を記録するだけで、表は常にコンパイルする。

拡張は、D16 (`13-decisions.md`) の原則「上流ツールが無視するか説明文として読む形で書く」に従う。ただしコールトークンと表の指示子は木の構造そのものなので、この原則を守れない拡張がある (次節の表の「非互換」)。その場合は `NonStandardToken` (Info) などで著者に見えるようにしている。

### 1.2 拡張の一覧と上流ツールでの扱い

| 拡張 | 形 | 本書 | 上流ツール (`bml.py` / `bss.py`) での扱い | 本コンパイラの Lint |
| --- | --- | --- | --- | --- |
| メタキー | `#+STRENGTH:` `#+NATURAL:` `#+DISTPOINTS:` `#+TIEBREAK:` `#+BALANCED:` `#+CONVENTION:` `#+RECOGNITION:` `#+VERSION:` | §6.5 | 無視 (任意の `\w+` キーを `meta` に入れるだけ) | 値の誤り: `UnknownDirective` (Warning) |
| 優先度 | 説明文中の `{prio:N}` | §6.1 | 説明文の一部として表示される | なし |
| 枝の重み | 説明文中の `{w:X}` | §6.2 | 説明文の一部として表示される | なし |
| システム停止 (行) | 説明文中の `{stop}` | §6.3、§7.7 | 説明文の一部として表示される | `StopUnderForcing` (Warning) |
| システム停止 (指示子) | 表の中の行 `#STOP` | §2.10、§7.7 | 非互換: 未知の行 (表の行として読めず、上流では誤読か失敗) | 同上。置き場所の誤り: `UnknownDirective` |
| 変数の順序を外す | 表の中の行 `#ANYORDER` | §2.10、§4.2 | 非互換: 未知の行。展開は順序つき (本コンパイラの展開の部分集合) になる | `AnyOrderWithoutVariables` (Info) |
| 裸のダブル・リダブル | `X`、`XX` | §4.1 | 非互換: `bid_type()` が読めない | `NonStandardToken` (Info) |
| 代替コール | `2S/3H`、`4D/H` | §4.5 | 非互換: `2S/3H` は末尾 2 文字だけ黙って残り、`4D/H` はクラッシュ | `NonStandardToken` (Info) |
| 全レベル | `nX`、`(nX)`、`nS` | §4.3 | 非互換: クラッシュ | `NonStandardToken` (Info)、候補が 8 を超えると `WideWildcard` (Info) |
| 相対レベル | `cS`、`jY`、`cM` | §4.3 | 非互換: レベルとして読まない | `NonStandardToken` (Info)、`LevelWithoutAnchor` (Error)、`NoSufficientLevel` (Info) |
| 小文字の変数 | `1x`、`2y`、`3z` | §4.2 | 非互換: 誤読かクラッシュ (`06-system.md` §1.4) | `NonStandardToken` (Info) |
| 相手のコールの類 | `(any)`、`(bid)`、`(suit)` | §4.6 | 非互換 | `NonStandardToken` (Info) |
| アラート印 | 説明文の先頭の `!` (直後が小文字の `c d h s` でないとき) | §3.6 | 説明文の一部として表示される (上流の著者の慣例) | なし |
| 説明文中の `#` | `5+#`、`0--1#` | §5.3 | 説明文の一部として表示される | なし |
| スート長の比較 | `!s>=!h`、`M>oM` | §5.4.12 | 説明文の一部として表示される | なし |
| 説明文の語彙全体 | `12--14 hcp, 5+!s, GF` など | §5 | 上流は説明文を解釈しない (表示するだけ) | `UnrecognizedFragment` ほか |

「非互換」の拡張を使ったファイルは、上流ツールでは正しく処理されない。上流との可搬性が要るファイルでは、`NonStandardToken` (Info) の出る行を避けるか、上流用の別ファイルに書き分ける。

### 1.3 Python 実装との意図的な差分

上流の正しいファイルの扱いでも、次の点は意図的に上流と違う。

1. **インデントの単位**。上流は固定の単位 (既定 2) を強制し、違反は `IndentationError` で止まる。本コンパイラは表ごとに最初の親子の差を単位とし、違う差は `IndentationMismatch` (Warning) を出して最も近い浅い行の子にする (§3.2)。
2. **末尾記号の無い履歴行の後の列 0 の行**。上流は新しいオープニングとして読む。本コンパイラは著者の意図どおり履歴の子として読み、`ColumnZeroContinuation` (Info) を出す (§3.4)。
3. **Exact 行はパターン行に勝つ**。上流 README の意図どおり、兄弟の間では Exact 行を行順に先に展開し、パターン行はその後に展開する (`bss.py` は実際には行順)。同じコールを作るパターン行は `ShadowedByExact` (Info) で捨てる (§4.8)。
4. **非標準のトークンを受理する**。`2S/3H`、`4D/H`、`nX`、`X`/`XX`、小文字の `x/y/z` (上流: クラッシュか誤読)。それぞれ `NonStandardToken` (Info) を付ける。
5. **エラーは行単位**。読めない行はその行と部分木だけを捨て、ファイルの残りはコンパイルする (§3.7)。
6. **説明文をコンパイルする**。上流は説明文を表示するだけだが、本コンパイラは説明文を手の制約 (`HandConstraint`) にコンパイルする (§5)。
7. **席は条件**。`#SEAT` はオープナーの席位置の条件で、先頭のパスは経路に含めない (上流の BSS も同じ符号化。D17)。
8. **同一条件の再定義で空の説明を埋める**。上流の「後の定義は空の説明を埋めるときだけ効く」を、席・バル条件の包含関係にまで広げる (§4.8)。

## 2. ファイル構造

### 2.1 行、段落、空白

- ファイルは行の列である。行末は `\n` か `\r\n` (Rust の `str::lines` で分ける)。
- **段落** は 1 行以上の空行 (空白だけの行を含む) で区切られた行の塊である。段落の種類 (§2.2) は段落の最初の行で決まる。
- 字下げは **半角スペースだけ** を数える。タブは字下げに数えない (タブで字下げした行は列 0 の行として読まれ、トークンの一部にもなる)。字下げにはスペースを使う。
- コールトークンと説明文は **最初のスペース** で区切る (タブではない)。

### 2.2 段落の分類

段落の最初の行 (先頭の空白を除く) を次の順に調べ、最初に当てはまる種類とする (上流の順序に合わせてある)。

| 順 | 条件 | 種類 |
| --- | --- | --- |
| 1 | `*` で始まる | 見出し |
| 2 | `-` で始まる | 箇条書き |
| 3 | `#VUL` で始まる | バル条件 (§2.7) |
| 4 | `#SEAT` で始まる | 席条件 (§2.6) |
| 5 | 数字の列の直後に `.` があり、その後が空白か行末 | 番号付き箇条書き |
| 6 | 最初の語 (空白までの文字列) 全体がコールトークン (§4) か履歴 (§3.4) として読める。ただし相対レベル (`c`/`j`) のトークンを除く | ビディング表 |
| 7 | `#+` の直後が英数字か `_` | メタ行 (§6.5) |
| 8 | `#` で始まる | 指示子つきのビディング表 (§2.10) |
| 9 | それ以外 | 地の文の段落 |

**落とし穴**: 規則 6 は「最初の語がコールとして読めるか」だけを見る。地の文の段落が `P`、`D`、`R`、`X`、`XX`、`1C`、`2NT`、`(1H)` などの語、あるいは **`any`、`bid`、`suit`** (相手の類のトークン §4.6 が括弧なしでも読めるため) で始まると、その段落はビディング表として読まれる。地の文をこれらの語で始めないこと (例: 「bid ...」ではなく「A bid ...」)。逆に、相対レベルの行 (`cS = ...`) で始まる段落は表にならず地の文になり、`UnknownCallToken` (Warning) が出る (§4.3)。

### 2.3 注釈 (コメント)

- **列 0 の `//`** で始まる行だけが注釈で、読み込みの段階で行ごと消える (段落の区切りにもならない)。
- 字下げした `//` や、行の途中の `//` は注釈ではない (表の中では説明文の一部、地の文では本文)。

```bml
// This whole line is dropped before paragraphs are formed.
1C = 12--21 hcp, 3+!c
// A column-0 comment between two rows keeps them in one table.
1D = 12--21 hcp, 3+!d
```

### 2.4 `#INCLUDE`

```text
include = WS0 , "#" , WS0 , "INCLUDE" , WS0 , PATH , [ WS , { CHAR } ] , NL ;
```

- 上流の正規表現 `^\s*#\s*INCLUDE\s*(\S+)` と同じく、字下げした `#INCLUDE` や `# INCLUDE` も受理し、キーワードの後の最初の語だけがパスで、残りは無視する。
- **パスは、包含する側のファイルのディレクトリからの相対パス** (絶対パスも可)。`/` と `\` はどちらも区切りとして読み、`.` と `..` を正規化する。Windows の `C:` のドライブ接頭辞は根として扱う。
- 包含したファイルの行は `#INCLUDE` の行の位置に差し込まれ、**前後に空行が 1 行ずつ入る** (上流の `'\n' + text + '\n'` と同じ)。したがって包含されたファイルは必ず自分の段落で始まり、自分の段落で終わる。連続する 2 つの `#INCLUDE` の表が 1 つの表に融合することは無い。
- `#SEAT` / `#VUL` の状態 (§2.6) とクリップボード (§2.9) はファイルの境を越えて引き継がれる (全ファイルを 1 本の行の列として読むため)。
- 見つからないファイルは `IncludeNotFound` (Warning) を出してその行を捨てる。循環か 16 段を超える入れ子は `IncludeCycle` (Error)。
- 読み込みは `SourceLoader` を通る。`FsLoader` はファイルシステムから、`MemLoader` はメモリ上の `(パス, テキスト)` の表から読む (wasm などファイルシステムの無い環境用)。

```bml,file=parts/openings.bml
1C = 12--21 hcp, 3+!c
1D = 12--21 hcp, 3+!d
```

```bml
#+TITLE: Include demo

#INCLUDE parts/openings.bml

1C-
1H = 6+ hcp, 4+!h
```

### 2.5 見出し、箇条書き、地の文

- 見出し (`*`、`**`、…)、箇条書き (`-`)、番号付き箇条書き (`1.`)、地の文の段落は、コンパイラにとっては文書の飾りである。展開にも制約にも影響しない (`BmlFile.blocks` に残るだけ)。
- 箇条書きの 2 行目以降で記号の無い行は、直前の項目の続きになる。
- 見出しは `#SEAT` / `#VUL` の状態をリセットしない。

### 2.6 `#SEAT` (オープナーの席)

```text
seat = "#SEAT" , WS , ( "0" | "1" | "2" | "3" | "4" | "12" | "34" ) ;
```

- `#SEAT s` は、それ以降の全ての表 (次の `#SEAT` まで、`#INCLUDE` の境を越えて) に付く条件で、**オープニングビッドが行われた席の位置** を指す。先頭のパスが k 個ならオープナーの位置は k + 1 (1 = ディーラーがオープン)。
- `0` = どこでも (既定)、`1`〜`4` = その位置、`12` = 1 か 2、`34` = 3 か 4。
- 先頭のパスは経路に含めない。`#SEAT 34` の表に `1H-` と書けば、「3 席目か 4 席目でオープンした 1H の後」を意味する (パスを書かない)。
- 相手のオープニングの表 (`(1H)-` で始まる表) でも、条件は「その相手のオープナーの位置」である。
- 読めない値は `UnknownDirective` (Warning) を出し `0` として扱う。
- `#SEAT` は段落 (空行で区切った 1 行) として書く。表の中に書いても効かない (表の中の未知の指示子として `UnknownDirective`)。

### 2.7 `#VUL` (バルネラビリティ)

```text
vul = "#VUL" , WS , TRI , TRI ;       TRI = "Y" | "N" | "0" ;
```

- 1 文字目が我々、2 文字目が相手のバル。`Y` = バル、`N` = ノンバル、`0` = どちらでも。例: `#VUL YN` は我々だけバル、`#VUL 0Y` は相手がバル、`#VUL 00` で解除。
- 以降の全ての表に付く (§2.6 と同じく粘着的)。読めない値は `UnknownDirective` (Warning) で `00`。

同じ位置に条件の違う定義があるときの選び方は §4.8 と §7.1。

```bml
1H = 12--21 hcp, 5+!h

#SEAT 34

1H-
2C = 10--11 hcp, 5+!c, 3+!h

#SEAT 0

#VUL YN

1H-
3H = 10--12 hcp, 4+!h

#VUL 00
```

### 2.8 メタ行

`#+KEY: value` の段落。§6.5 で詳述する。1 つの段落に何行でも書け、`#+` で始まらない行や `:` の無い行は `UnknownDirective` (Warning)。

### 2.9 クリップボード: `#COPY`、`#CUT`、`#PASTE`

表の一部を名前付きで保存し、別の場所へ貼り付ける (上流と同じ。テキストの置換である)。

| 指示子 | 意味 |
| --- | --- |
| `#COPY name` … `#ENDCOPY` | 間の行をクリップボード `name` に保存し、**その場にも残す** |
| `#CUT name` … `#ENDCUT` | 間の行をクリップボード `name` に保存し、その場からは **取り除く**。段落全体が `#CUT` … `#ENDCUT` なら、表を作らないクリップボード専用の段落になる |
| `#PASTE name [tgt=rep …]` | クリップボード `name` の行をここに差し込む。各行の先頭に `#PASTE` 行の字下げを付け、`tgt=rep` の置換を **書いた順に** 単純な文字列置換として行う |

- 保存する本文は、`#COPY` / `#CUT` 行の字下げの分だけ左へずらす。貼るときに `#PASTE` 行の字下げを足すので、クリップボードの本文は列 0 基準で書き、貼る側で深さを決める。
- 名前の再定義は、**後の定義がそれ以降の貼り付けに効く** (上流の辞書と同じ)。
- 貼った本文の中の `#PASTE` も展開する (字下げは積み重なる)。16 段を超える入れ子 (自分自身を貼るクリップボード) は `UnknownDirective` (Warning) で打ち切る。
- 無い名前の `#PASTE` は `PasteUnknownName` (Warning)。`#ENDCUT` / `#ENDCOPY` の無い開始は `UnknownDirective` (Warning) で、その開始行だけを捨てる。
- 処理の順は、段落ごとに `#CUT` を全部抜き出し、次に `#COPY`、最後に `#PASTE` を展開する。したがって同じ段落の中でも、`#PASTE` は同じ段落の後ろにある `#CUT` の本文を使える。
- 置換は字句の置換なので、`\R=D` のように、本文に他に現れない印を使う (上流の慣例は `\` で始まる印)。印は語の境界を問わず全ての出現を置き換える。
- 貼られた行の位置 (`Span`) は `#PASTE` の行を指し、`pasted_from` にクリップボード名と本文の行番号が入る。

```bml
#CUT transfer
2\R = !TRF, 5+\M
  2\S = 2+\M
#ENDCUT

1N = 15--17 hcp, bal

1N-
2C = !STAY, 8+ hcp
#PASTE transfer \R=D \M=!h \S=H
#PASTE transfer \R=H \M=!s \S=S
```

1 つ目の `#PASTE` は `2D = !TRF, 5+!h` とその子 `  2H = 2+!h` を、2 つ目は `2H = !TRF, 5+!s` と `  2S = 2+!s` を差し込む。置換は本文の全ての出現に効くので、コールトークンに入れる印 (`\S` はストレインの文字) と説明文に入れる印 (`\M` はスート記号) を分けている。同じ印を両方に使うと、例えば子の行が `2!h` になり、コールトークンとして読めずに `UnknownCallToken` (Warning) になる。

### 2.10 表の中の指示子

ビディング表の段落の中 (行と行の間、または最初の行の前) に、`#` で始まる 1 行の指示子を書ける。前後の空白は無視する。

| 指示子 | 意味 | 由来 |
| --- | --- | --- |
| `#HIDE` | 表に「隠す」印を付ける (`BidTable.hidden`)。コンパイルには影響しない | 上流 (BSS にだけ出す) |
| `#BIDTABLE` | 何もしない (上流では段落を表として扱わせる。本コンパイラは段落の最初の行が `#` なら表として読むので不要) | 上流 |
| `#COPY` / `#CUT` / `#PASTE` / `#ENDCOPY` / `#ENDCUT` | §2.9 | 上流 |
| `#STOP` | システム停止。行の子の位置 (その行より深い字下げ) に書くとその行の後に、表の最上位 (字下げ 0) に書くと表の履歴の位置に停止を置く (§7.7) | 拡張 |
| `#ANYORDER` | その表全体で、新しく束縛する `X`/`Y`/`Z` の `X < Y < Z` の順序を外す (§4.2)。表のどこに書いても表全体に効く | 拡張 |
| その他の `#…` | `UnknownDirective` (Warning) を出して、その行を無視する | |

- `#STOP` と `#ANYORDER` は、表と同じ段落に書く。空行で区切った独立の段落 (`#SEAT` のような書き方) に書くと表を名指さないので効かず、`UnknownDirective` (Warning) が出る。
- 履歴の無い表の最上位の `#STOP` は位置を名指さないので、`UnknownDirective` (Warning) を出して無視する。

```bml
1C = 12--21 hcp, 3+!c

1C-
1H = 6+ hcp, 4+!h
  #STOP
1N = 6--10 hcp
2C = 11+ hcp, 5+!c
P = {prio:-100} {stop} any hand

1C-2C-
#STOP
2N = 13--15 hcp, bal
```

## 3. ビディング表

### 3.1 行

```text
row      = WS0 , calltok , [ WS , [ "=" , WS0 ] , description ] , NL , { contline } ;
```

- 行は「字下げ、コールトークン、空白、説明文」である。コールトークンの直後の `=` は省略できる糖衣 (`1C = 12+ hcp` と `1C  12+ hcp` は同じ)。
- コールトークンは行頭の空白の後から **最初のスペースまで** の文字列全体で、その全体が §4 の `calltok` として読めなければならない (読めなければ §3.7)。
- 説明文の先頭の `!` はアラート印 (§3.6)。
- 説明文は省略できる (空の説明: 制約なし、`EmptyDescription` (Info))。

### 3.2 字下げと木

- 字下げが行の木を作る。ある行より字下げの深い次の行はその子、同じか浅い行はその行を閉じて、字下げがより浅い祖先の子 (祖先が無ければ表の最上位の行) になる。
- **子の行は、親の行が表すコールの後の、次の手番のコール** を表す (相手の手番を挟む場合は暗黙のパス §3.5)。
- **字下げの単位は表ごとに推定する**: 表の中で最初に現れた「親から子への字下げの差」がその表の単位である。以後、差が単位と違う子は `IndentationMismatch` (Warning) を出すが、捨てずに最も近い浅い行の子にする。単位は 2 でも 4 でもよいが、1 つの表の中では揃える。
- 表の最上位の行どうしは字下げが違ってもよい (単位の検査は親子の間だけ)。

### 3.3 継続行

- **前の行の説明文が始まった桁と同じ字下げ** の行は、その説明文の続きになる (`\n` で連結。行末の空白は落とす)。
- この規則の帰結として、子の行を親の説明文と同じ桁から始めることはできない (続きとして読まれる)。子は説明文より浅く字下げする。
- コールトークンだけで説明文の無い行 (トークンの後に空白も `=` も無い行) には続きが無い。
- 継続行の中の列挙 (`a)`、`1)` …) は選言になる (§5.3)。

```bml
1C = one of:
     a) 12--14 hcp, bal
     b) 15+ hcp, 5+!c
  1D = 0--7 hcp
```

ここで `a)` と `b)` の行は `1C` の説明の続き (説明文が 5 桁目から始まり、続きも 5 桁目)、`1D` は字下げ 2 の子である。

### 3.4 履歴行

表の **最初の行** のコールトークンが `-` か `;` を含むなら、その行は **履歴行** である。

```text
history-row = WS0 , seq , [ WS , [ "=" , WS0 ] , description ] , NL , { contline } ;
seq         = calltok , { ( "-" | ";" ) , calltok } , { "-" | ";" } ;
```

- 履歴行は、表の行が続く位置までのオークション (オープニングから) を書く: `1N-2C;`、`1C-`、`1C---`、`1C-1D;`、`(1NT)---`、`(1N)-P-(P)---`、`1C-(1D)-`。区切りは `-` でも `;` でもよく、末尾の `-`/`;` の個数は見た目だけである (区切りを 2 つ続けられるのは末尾だけ)。
- 表の行は全て、履歴の最後のコールの子になる (表の最上位の行 = 履歴の後の次の手番のコール)。
- 履歴の途中の暗黙パスは §3.5 の規則で補う (`1N-2C` は `1N (P) 2C`)。
- 履歴行に書いた説明文は **履歴の最後のコール** のものになる。
- 履歴の中の変数 (`(1X)-`、`1M-2N-`) はそこで束縛され、表の全ての行から見える。変数が複数の候補を持てば、表の残り全体が候補ごとに展開される。
- 履歴の中のコールは、他の表が既に定義していれば同じノードを再利用する (説明が空なら何も上書きしない)。履歴だけで初めて現れるコールは説明が空の「プレースホルダ」ノードになり、後で同じ位置を定義した行がそれを埋める (§4.8)。
- **末尾の記号が無い履歴行** (`1N-2C`) も履歴である。その後の列 0 の行は履歴の子として読み (上流とは違う。§1.3 の 2)、`ColumnZeroContinuation` (Info) を出す。字下げした行なら Lint は出ない。
- 表の 2 行目以降に `-` か `;` を含むトークンがあると `SequenceNotFirst` (Error) で、その行と部分木を捨てる。

```bml
1N = 15--17 hcp, bal

1N-2C-
2D = no 4 card major
2H = 4+!h
2S = 4+!s, 0--3!h

1N-2C
  3N = 10--15 hcp, to play
```

### 3.5 相手のコールと暗黙パス

- 相手のコールは **括弧** で書く: `(1N)`、`(D)`、`(P)`、`(2Y)`、`(any)`。括弧の無いトークンは我々のコールである。
- 経路の上で **同じ側のコールが 2 つ続くと、その間に反対側のパスを補う** (暗黙パス)。我々のコール 2 つの間には相手の `(P)` が、相手のコール 2 つの間には我々の `P` が入る。したがって競り合いの無い `1N` → `2C` → `2D` は `1N (P) 2C (P) 2D` の 5 コールを表す。
- 暗黙パスはトライの辺を持つが、ノード (行) は持たない。**相手がパス以外のコールをした実際のオークションは、暗黙パスの辺には乗らない**。競り合いのある経路は、相手のコールを明示した表 (`1C-(1S)-` や `1C-(any)-`) で書く。
- 先頭のパスは経路に含めない (§2.6)。表の最初のコールがオープニングである。
- どちらの側のパスでも、実際にそのパスを書いた表でだけ辺ができる。例外はシステム停止 (§7.7) で、停止の後は相手の任意のコールと我々のパスの辺がトライに接がれる。

```bml
1S = 12--21 hcp, 5+!s

1S-(2H)- = 5+!h
3H = !CUE, 10+ hcp, 3+!s
D = 10+ hcp, 0--2!s
P = {prio:-100} any hand

1S-(D)- = t/o, 12+ hcp
2N = !Jordan, 10+ hcp, 4+!s
XX = 10+ hcp
```

### 3.6 アラート印

- 説明文 (最初の行) の先頭の `!` で、直後が小文字の `c`、`d`、`h`、`s` **でない** ものはアラート印である。コールを「アラート対象」(`Alertability::Alertable`) にし、ノードの `flags.artificial` を立てる。印自体は説明文から取り除く。
- `!c !d !h !s` はスート記号 (§5.2) なので、`!s` で始まる説明文はアラート印ではない。スートで始まるアラートは `! !s …` のように `!` と空白を先に書く。
- `!Michaels`、`!TRF`、`!STAY` のような書き方は、アラート印 + 語 (`Michaels` など) である。
- 履歴行の説明文にも同じ規則が働く。

### 3.7 回復規則 (読めない行)

コンパイルはファイル全体では失敗しない。読めない部分は Lint を出して、その部分だけを捨てる。

| 状況 | 扱い | Lint |
| --- | --- | --- |
| コールトークンとして読めない行 | その行と部分木 (より深い字下げの行) を捨てる | `UnknownCallToken` (Warning) |
| 読めない履歴行 | その行と部分木を捨てる | `UnknownCallToken` (Warning) |
| 2 行目以降の履歴形 (`-`/`;` を含む) | その行と部分木を捨てる | `SequenceNotFirst` (Error) |
| 単位と違う字下げ | 最も近い浅い行の子にする | `IndentationMismatch` (Warning) |
| 未知の指示子 | 無視する | `UnknownDirective` (Warning) |
| 相対レベルで始まる段落 | 地の文として読む (中の行は全て失われる) | `UnknownCallToken` (Warning) |

## 4. コールトークン

### 4.1 形の一覧

`calltok` は 1 つのコール (または、コールの集合を表すパターン) を書く。括弧で囲むと相手のコール、囲まなければ我々のコールである (§3.5)。字句は **大文字と小文字を区別する** (`P` はパス、`p` は読めない。`M` はメジャー、`m` はマイナー)。例外は `red`/`black` と `step`/`steps` で、これらは大小を問わない。

| 形 | 例 | パターン (`CallPattern`) | 意味 | 上流 |
| --- | --- | --- | --- | --- |
| `P` | `P`、`(P)` | `Exact(Pass)` | パス | 上流 |
| `D`、`X` | `D`、`(X)` | `Exact(Double)` | ダブル。`X` は拡張 (`NonStandardToken`) | `D` は上流 |
| `R`、`XX` | `R`、`(XX)` | `Exact(Redouble)` | リダブル。`XX` は拡張 (`NonStandardToken`) | `R` は上流 |
| レベル + 1 ストレイン | `1C`、`2D`、`3H`、`4S`、`1N`、`3NT` | `Exact(Bid)` | そのビッド。`N` と `NT` は同じ | 上流 |
| レベル + 複数スート | `2CD`、`3HS`、`4CDHS` | `Strains{level, strains}` | 列挙したスートのどれか。`N` は他のスートと組めない (`2CN` は読めない) | 上流 |
| レベル + `red`/`black` | `2red`、`3black`、`2Red` | `Strains` (D+H / C+S) | 赤 (D、H) / 黒 (C、S) のスート | 上流 (BML 2) |
| レベル + 変数 | `2M`、`3m`、`2oM`、`1X`、`2Y`、`3Z`、`1x` | `Var{level, var}` | §4.2 | 上流 (小文字 `x/y/z` は拡張) |
| 全レベル | `nS`、`nX`、`(nX)` | `Strains`/`Var` (`Level::Any`) | そのストレインの **十分な全てのレベル** (§4.3) | 拡張 |
| 相対レベル | `cS`、`jH`、`cM`、`jY` | `Strains`/`Var` (`Level::Cheapest`/`Jump`) | そのストレインの最も安い十分なビッド (`c`)、その 1 つ上 (`j`) (§4.3) | 拡張 |
| ステップ | `1step`、`2steps`、`3STEPS` | `Step(n)` | オークションの最後のビッドから n 段上のビッド (§4.4) | 上流 |
| 代替 | `2S/3H`、`4D/H`、`P/2C`、`2S/cH` | `AnyOf` | 列挙したパターンのどれか (§4.5) | 拡張 |
| 相手の類 | `(any)`、`(bid)`、`(suit)` | `Class(OppClass)` | 相手の任意のコール / 任意のビッド / 任意のスートビッド (§4.6) | 拡張 |

- `N` と `NT` のどちらでも書ける (`1N`、`1NT`)。スートの文字は `C D H S` の大文字だけ。
- レベルは `1`〜`7` の 1 桁、`n` (全レベル)、`c` (最安)、`j` (ジャンプ)。`8C` や `0C` は読めない。
- トークン全体が読めなければならない。`1Cx` や `2S!` は `UnknownCallToken` (Warning)。
- 字句の試行順は `XX`、`X`、`P`、`D`、`R`、`any`/`suit`/`bid`、ステップ、レベル + ストレイン。レベル + ストレインの中では `red`/`black`、変数、リテラルの順。

### 4.2 変数

| 変数 | 取りうるストレイン | 束縛 |
| --- | --- | --- |
| `M` | H、S | 最初の出現で束縛。以後の `M` は同じスート |
| `m` | C、D | 同上 |
| `oM` | `M` でない方のメジャー | 束縛しない。`M` が束縛済みであること |
| `om` | `m` でない方のマイナー | 束縛しない。`m` が束縛済みであること |
| `X`、`Y`、`Z` (と小文字の `x`、`y`、`z`) | C、D、H、S | 最初の出現で束縛。`X < Y < Z` (C < D < H < S) の順序を保つ |

**束縛の範囲**。変数の束縛は、その表の中で経路 (履歴 + 行の祖先 + その行) に沿って有効である。履歴で束縛した変数は表の全ての行から見え、行で束縛した変数はその行の部分木から見える。兄弟の行は互いの束縛を見ない (兄弟ごとに独立に展開する)。表をまたいで束縛は引き継がれない。

**展開**。未束縛の変数は候補ごとに行 (と部分木) を複製する。候補は次の規則で絞る。

1. **既に使われたストレインを除く**。経路で (どちらの側でも) 既にビッドされたスートは候補にならない。したがって束縛済みの変数どうしは必ず違うスートになる (束縛済みのスートはビッドされているため)。`M` と `X` は別々の変数だが、同じ理由で違うスートになる。
2. **`X < Y < Z` の順序**。束縛済みの変数に対して順序を保つ候補だけを残す (例: `Y` が H に束縛済みなら、新しい `X` は C か D、新しい `Z` は S)。表に `#ANYORDER` があると、その表では新しく束縛する `X`/`Y`/`Z` の順序を外す (異なるスートであることは規則 1 で保たれる)。`#ANYORDER` を書いたのに表が `X`/`Y`/`Z` を 2 つ以上使っていなければ `AnyOrderWithoutVariables` (Info)。
3. **十分なビッドだけ**。新しく束縛する変数は、オークションの最後のビッドより高いビッドになる候補だけを生む (上流の `check_vars` と同じ)。`(1S)-` の後の `2X` は 2C、2D、2H になる (2S はスペードが使用済み)。

束縛済みの変数 (と固定レベル) のコールは候補を絞らない。不十分なビッドになれば `IllegalCall` (Error) でその行を捨てる (同じ行が別の束縛では成功していれば Info に下げる。変数の展開で一部の候補だけが不十分になるのは普通のことだから)。

- 候補の無い新しい変数は `VariableNoCandidate` (Info) で、その行を捨てる。
- 未束縛の `oM`/`om` は `UnboundOther` (Error)。
- 相手の類のワイルドカード (`(any)` など §4.6) の下では、新しい変数は候補を持たない (相手の実際のコールが分からないので、どのスートが使用済みかが決まらない)。

説明文の中の変数は、その行の束縛で置き換わる (§5.3)。

```bml
1M = 12--21 hcp, 5+M

1M-
2M = 6--10 hcp, 3+M
3M = 10--12 hcp, 4+M
2oM = 10+ hcp, 5+oM
```

`1M` は `1H` と `1S` の 2 つのオープニングになり、その下の `2M` は 1H の下では `2H`、1S の下では `2S` になる。1S の下の `2oM` は `2H` だが、1H の下の `2oM` (= `2S`) も十分なビッドなので両方できる。

```bml
(1X)- = 12+ hcp, 3+X
2Y = 10+ hcp, 5+Y
D = t/o, 12+ hcp
```

`(1X)` は相手の 1C、1D、1H、1S の 4 つの表になり、`2Y` はそれぞれ X より高いスートの 2 のビッドだけになる (1S の後は候補が無く `VariableNoCandidate`)。順序を外すと、`Y` は X 以外の全てのスートになる。

```bml
(1X)- = 12+ hcp, 3+X
#ANYORDER
2Y = 10+ hcp, 5+Y
```

### 4.3 全レベル `n` と相対レベル `c`・`j`

- `n` は **十分な全てのレベル** を表す: `nS` はオークションの最後のビッドより高い 1S〜7S の全て。`(nX)-` は「相手の任意のレベルの任意のスートのオープニングの後」である。候補が 8 を超えると `WideWildcard` (Info) を出す (`(nX)` は 28 の表になる)。
- `c` は、そのストレインの **最も安い十分なビッド** (オークションにビッドが無ければ 1 のレベル)。`j` はその 1 つ上のレベル。7 を超える候補は無い (`NoSufficientLevel` (Info) で行を捨てる)。
- 相対レベルは、オークションの最後のビッドが展開時に分かっていることを要する。相手の類のワイルドカード (`(any)`、`(bid)`、`(suit)`) の下で、そのワイルドカードがビッドでありうるときは最後のビッドが決まらないので `LevelWithoutAnchor` (Error) になり、行を捨てる (1 つの範囲につき 1 回)。
- **相対レベルの行で段落を始めることはできない** (§2.2 の規則 6)。相対レベルの行は、表の 2 行目以降か、履歴行の後に置く。

```bml
1H = 12--21 hcp, 5+!h

1H-(1S)-
cH = 6--10 hcp, 3+!h
jH = 0--6 hcp, 4+!h
cN = 10--12 hcp, stopper in !s
```

`1H-(1S)-` の後の `cH` は 2H、`jH` は 3H、`cN` は 1N である。

### 4.4 ステップ

- `<n>step` / `<n>steps` は、オークションの **最後のビッド** (どちらの側のものでも) からストレインの順 (C < D < H < S < NT) で n 段上のビッドである。`1N-2C-` の後の `1step` は 2D、`2steps` は 2H。
- n は 1 桁に限らない (`9steps` も書ける)。
- 最後のビッドが無い、7NT を超える、あるいは相手の類のワイルドカードの下 (最後のビッドが決まらない) では `StepWithoutAnchor` (Error) で行を捨てる。

```bml
2C = 22+ hcp

2C-2D-
2H = 5+!h
  1step = 0--3 hcp
  2steps = 4+ hcp
```

`2C-2D-2H` の後の `1step` は 2S、`2steps` は 2NT である。子の行の位置を履歴で書き直すことはできない。表の 2 行目以降の `-` を含むトークンは `SequenceNotFirst` (Error) で、その行と部分木が失われる。

```bml,should-lint
// expect-lint: SequenceNotFirst
2C = 22+ hcp

2C-2D-
2H = 5+!h
  2H-
  1step = 0--3 hcp
```

### 4.5 代替

- `/` で区切ったパターンのどれか: `2S/3H`、`P/2C`、`(1H/1S)`。
- `/` の後にレベルの無いストレインを書くと、直前のレベルを使う: `4D/H` は `4D/4H`、`2S/cH` の `cH` は相対レベル。
- 各代替は独立に展開される (変数を含む代替では、束縛も代替ごとに違う)。行の説明文は全ての代替に共通である。
- `/` を使うと `NonStandardToken` (Info) が出る (上流では読めない)。

```bml
1S = 12--21 hcp, 5+!s

1S-
3C/3D = 10--12 hcp, 6+ card suit
```

### 4.6 相手の類 `(any)`、`(bid)`、`(suit)`

| トークン | 類 (`OppClass`) | 当てはまる相手のコール |
| --- | --- | --- |
| `(any)` | `AnyCall` | 全てのコール (パス、ダブル、リダブル、ビッド) |
| `(bid)` | `AnyBid` | 全てのビッド (NT を含む) |
| `(suit)` | `AnySuitBid` | NT 以外のビッド |

- トライには 1 本の **ワイルドカードの辺** として入り、実際のオークションでは相手のコールがその類に当てはまれば辿る (§7.1)。同じ位置に相手の具体的なコールの辺 (`(2H)` など) もあれば、具体的な辺を先に試す。
- 類の下の行 (`1S-(any)-` の表の行) は、相手の実際のコールが分からないまま展開する。そのため:
  - 固定レベルのコールは十分性を検査しない (`1S-(any)-` の `2H` は、相手が 3C をしたときには選べないだけで、コンパイルでは Error にならない。実行時に合法性で除かれる)。
  - 新しい変数は候補を持たない (`VariableNoCandidate`)。束縛済みの変数は使える。
  - ステップは `StepWithoutAnchor` (Error)、相対レベルは類がビッドを含むとき `LevelWithoutAnchor` (Error)。
- 類に当てはまるコールがその局面で一つも無い (例: 相手が既にダブルした後の `(any)` は常にありうるが、7NT の後の `(bid)` は無い) 候補は捨てる。
- 類のトークンは括弧で囲むのが正しい書き方である。括弧の無い `any` / `bid` / `suit` も **我々の** 類のコールとして読めてしまう (未定義の動作。段落の分類 §2.2 の落とし穴の原因でもある)。
- 類を使うと `NonStandardToken` (Info) が出る。`(any)` は小文字の `y` を含むので、理由が「小文字の変数 (x/y/z)」とも表示される (履歴行ではその理由だけが表示される)。実害は無い。

```bml
1S = 12--21 hcp, 5+!s

1S-(2H)- = 5+!h
3H = !CUE, 10+ hcp, 3+!s

1S-(any)-
4S = 0--9 hcp, 5+!s
P = {prio:-100} any hand
```

`1S` の後の相手の 2H では `1S-(2H)-` の表が使われ、それ以外の相手のコールでは `(any)` の表が使われる。

### 4.7 相手のコールと我々のコールの間の暗黙パス

§3.5 のとおり、経路の上で同じ側のコールが 2 つ続くと反対側のパスを補う。暗黙パスを補うとき、そのパスが合法でない (オークションが既に終わっている) 候補は捨てる。

### 4.8 同じ位置の複数の定義: 優先順位

同じ経路 (同じオークション) に 2 つ以上の定義が当たるときは、次の規則で決まる。

1. **兄弟の中では Exact 行がパターン行に勝つ**。同じ親の下の兄弟の行は、Exact 行 (`2H`、`P`) を行順に全て展開してから、パターン行 (`2M`、`2X`、`nS`、`2S/3H`、`(any)`) を行順に展開する。パターンの候補が先の Exact 行のコールと同じなら、その候補は捨てて `ShadowedByExact` (Info)。先のパターン行のコールと同じなら黙って捨てる (上流の `bid not in bids_processed`)。この展開の順は、優先度が同じ兄弟の順位 (`row-order`、§7.4) にもなる。
2. **先の定義が勝つ** (表をまたいでも、ファイルをまたいでも)。同じ経路・同じ席とバルの条件の 2 つ目の定義は:
   - 説明が違い、どちらも空でないなら、`DuplicatePath` (Warning) を出して後の定義を捨てる。部分木は先のノードの下に統合される。
   - 先の説明が空 (履歴だけで作られたプレースホルダ) なら、後の説明で埋めて `DuplicatePath` (Info)。
   - 後の説明が空なら、先のノードをそのまま使う (Lint なし。履歴行が既存のノードを辿るのはこの場合)。
3. **席とバルの条件が違う定義は共存する**。それぞれ別のエントリになり、実際のオークションでは **当てはまる条件のうち最も具体的なもの** が使われる。具体性は `席の具体性 × 3 + バルの具体性` で、席は `0` が 0、`12`/`34` が 1、単独の席が 2、バルは `Y`/`N` と指定した側の数 (0〜2)。
   - 条件の違う 2 つの定義が同じ具体性で重なる (両方に当てはまるオークションがありうる) と、`ConditionTie` (Info) を出し、先に入れた方が勝つ。
   - 後から入れた一般的な定義 (`#SEAT 0`) の説明で、先に入れた、より具体的なプレースホルダ (説明が空) を埋める。`DuplicatePath` (Info)。
4. **説明が空の行は、覆う定義を再利用する**。説明の無い行 (履歴や中継の行) は、同じ経路のより一般的な条件の既存のノードがあれば、新しいノードを作らずにそれを使う。

```bml
1N = 15--17 hcp, bal

#SEAT 34

1N = 14--16 hcp, bal

#SEAT 0

1N-
2C = !STAY, 8+ hcp
```

この例では、3 席目・4 席目の 1N は 14--16、それ以外は 15--17 である。`1N-` の表 (`#SEAT 0`) は両方の 1N の後に効く。

```bml,should-lint
// expect-lint: DuplicatePath
1C = 12--21 hcp, 3+!c
1C = 16+ hcp
```

## 5. 説明文の言語

説明文は、上流では表示するだけの自由な文章である。本コンパイラはこれを **手の制約** (`HandConstraint`: HCP、スート長・シェイプ、カードの要件、評価値の要件の論理式) と **フラグ** (人工的、フォーシング、…) にコンパイルする。読めない部分は捨てて Lint を出すだけで、コンパイルは止まらない。語彙の表 (§5.4) は `crates/bridge-system/src/compile/desc/{tokens,clause,recognition}.rs` の表から書き起こしてあり、試験 (§0.2) が全ての語の記載を確かめている。

処理は 5 段である。

1. **正規化** (§5.1): 注釈とアラート印を取り除き、スートの記法を揃える。
2. **節の構文** (§5.2): 行、列挙、区切り、否定、ヘッジで論理式の骨格を作る。
3. **語彙** (§5.4): 各断片を字句として認識する (文脈に依らない)。
4. **文脈** (§5.5): 役割、パートナーのレンジ、変数の束縛、`#+STRENGTH:` などから、文脈に依る語 (`GF`、`INV`、`weak`、…) の値を決める。
5. **組み立て** (§5.6): 論理式にまとめ、フラグを導き、認識率 (§5.7) を計る。

### 5.1 正規化

| 入力 | 扱い |
| --- | --- |
| `{prio:N}` | 優先度 (§6.1)。取り除く。N は符号付き 16 ビット整数 |
| `{w:X}` | 枝の重み (§6.2)。取り除く。X は実数 |
| `{stop}` | システム停止 (§6.3)。取り除く。括弧の中の前後の空白は可 (`{ stop }`) |
| その他の `{…}` | 普通の文字として残る (認識されなければ `UnrecognizedFragment`) |
| 先頭の `!` (直後が小文字の `c d h s` でないもの) | アラート印 (§3.6)。取り除き、`artificial` を立てる |
| `!c` `!d` `!h` `!s` | スート記号 `♣ ♦ ♥ ♠` に置き換える。説明文でスートを書く標準の方法 |
| `♣ ♦ ♥ ♠` | そのまま使える |
| `--` | `-` に置き換える (上流の範囲の書き方 `12--14` は `12-14` と同じ) |
| 連続する空白 | 1 つの空白にまとめる。改行は残す (継続行 §3.3 は行として残り、列挙に使われる) |

注釈は説明文のどこに書いてもよい。ノードの表示用の説明 (`Node::description`) からは注釈を取り除いたものが入る (`Row::description_raw` は元のまま)。

**大文字と小文字**。語彙の語は大小を問わない (`GF`、`gf`、`Gf` は同じ)。例外は変数の `M`、`m`、`oM`、`om`、`MM`、`mm` と、オナーの並び (`AKQxx`) で、これらは大小を区別する。

### 5.2 節の構文

```ebnf
description = line , { NL , line } ;
line        = enumitem | clauses ;
enumitem    = marker , WS , clauses ;          (* items of one description form an Or group *)
marker      = LETTER , ")" | DIGITS , ")" | DIGITS , "." | "(" , LOWER , ")" | "(" , DIGITS , ")" ;
clauses     = orgroup , { ( "," | ";" | "." ) , [ "or" | "/" ] , orgroup } ;
orgroup     = andgroup , { ( "or" | "/" ) , andgroup } ;
andgroup    = fragment , { ( "and" | "with" | "w/" | "+" | WS ) , fragment } ;
fragment    = [ negation ] , [ hedge , { filler } ] , atom ;
```

- **結合の強さ** (強い順): `and`・`with`・`w/`・`+`・空白 (暗黙の AND) > `or`・`/` > `,`・`;`・`.` (AND)。
  - `15-17 hcp, bal` は AND。`5+♥ or 5+♠, 10+ hcp` は `(5+♥ ∨ 5+♠) ∧ 10+`。
  - `A, B, or C` の形 (カンマの並びの最後の区切りの後に `or`) は、カンマの並び全体の OR である。
  - 2 つのスート長の断片の間の `-` も AND (`4+♠-4+♥`)。
- **行**。列挙の印で始まる行 (`a)`、`1)`、`1.`、`(a)`、`(1)`) は、1 つの説明文の中で 1 つの OR にまとまる。それ以外の行は全て AND で結ぶ (見出し行 `one of:` や共通の条件の行と列挙が並ぶ実際のファイルの書き方に合わせてある)。
  - **落とし穴**: 行頭の `(5431)` や `(1)` は列挙の印として読まれる。行頭でシェイプの類を書くときは `5431 or 5440` のように括弧を外すか、行の途中に書く。
- **否定**: 断片の前の `without`、`denies`、`not`、`no`、`w/o`、`non` (`non-` も) はその断片を否定する (`no 4 card major`、`denies 4+♥`、`non forcing` は語彙の語、§5.4.8)。
- **ヘッジ**: 断片の前のヘッジ語は `soft` (柔らかい制約) の印を付ける。2 種類ある。
  - **確からしさ** (`normally`、`typically`、`usually`、`likely`、`mostly`): リテラルを残す。`usually 15-17` は 15..17 の制約になる。
  - **可能性** (`occasionally`、`sometimes`、`possibly`、`perhaps`、`maybe`、`rarely`、`might`、`may`、`(?)`): リテラルを **捨てる** (その断片は何も要求しない)。`may have 4♠` は 4♠ を要求しない。
  - ヘッジの後の `be`、`have`、`hold`、`contain`、`include` は読み飛ばす (`may be 6♥`、`usually have 4♠`)。
  - ヘッジのある説明文には `SoftConstraint` (Info) が出る。
- **コールへの言及**。`to`、`over`、`after`、`for`、`than`、`via`、`opposite`、`like`、`see`、`from`、`into`、`then`、`by`、`bid`、`rebid`、`opening`、`open`、`bids`、`else`、`otherwise`、`instead` の直後のコールの形 (`2H`、`1N-2C`、`3♣`) と、昇順の `-` の連なり (`1N-2C-2D`) は、制約ではなく **言及** として 1 つの未認識の断片にまとめる (`transfer to 2H` の `2H` をスート長と誤読しないため)。`see …` の余談は次の区切りまで続く。
- **変数の置換**。行の束縛 (§4.2) で、説明文の中の `M`、`oM`、`m`、`om`、`X`、`Y`、`Z` を、語の境界 (直前に数字があってもよい: `5M`、`4+X`) でスート記号に置き換える。`1M = 5+M` の 1H の展開では `5+♥` になる。未束縛の `M`/`m` はそのまま残り、「どちらかのメジャー / マイナー」と読まれる。
- **`#`**。説明文の `#` は、経路を遡って最も近い、パターン (変数・複数スート・代替) から作られたコールのストレインを指す (`nX = 5+#`)。`#` 自体は置き換えず、文脈 (§5.5) で解決する。当てはまるコールが無ければ前提扱い (`AssumedContext`) で制約にならない。

### 5.3 スートの参照

スート長 (`5+♥`)、短さ (`singleton ♣`)、ストッパー (`stopper in ♠`) などの後に置けるスートの参照。数値との間に空白を 1 つ置いてもよい (`5+ ♥`、`6+ suit`)。

| 書き方 | 意味 |
| --- | --- |
| `♣ ♦ ♥ ♠` (`!c !d !h !s`) | そのスート |
| `#` | §5.2 の `#` |
| `M`、`oM` (大文字小文字を区別) | 束縛されていれば置換済み。未束縛ならどちらかのメジャー |
| `m`、`om` | 同じくマイナー |
| `card suit`、`cards`、`card`、`suits`、`suit` | その行のコールのスート (「自分のスート」)。コールがスートのビッドでなければ前提扱い |
| `majors`、`major` | どちらかのメジャー (H か S に指定の長さ) |
| `minors`、`minor` | どちらかのマイナー |

「どちらかのメジャー」は、スート長では 2 つのスートの論理和になる (`4+ major` は 4+♥ または 4+♠)。1 つのスートを要する語 (ストッパー、スートの質) では解決できず、前提扱いで制約にならない。

### 5.4 語彙

各表の語は、前にあるものほど先に試される (長い語を先に)。語は語の境界で終わらなければならない (`gfx` は `gf` ではない)。認識の順は次のとおりで、先の規則が当たればそこで決まる。

1. シェイプ (§5.4.4)
2. スート長の比較 (§5.4.5)
3. 数値の族 (§5.4.1〜§5.4.3)
4. 数値の無い `controls` / `control`
5. バランス (§5.4.6)
6. 句 `min/max`、`might be strong` (範囲なし §5.4.15)
7. 強さ (§5.4.7)
8. フォーシング (§5.4.8)
9. スプリンター (§5.4.9)
10. 慣習 (§5.4.10)
11. スートの質 (§5.4.11)
12. ストッパー (§5.4.12)
13. 短さ (§5.4.13)
14. ナチュラル (§5.4.14)
15. 範囲なし (§5.4.15)
16. 支持 (§5.4.3)

#### 5.4.1 数値: HCP、ポイント、コントロール、ルーザー

数値は 0〜99 の 1〜2 桁。

| 書き方 | 例 | 意味 |
| --- | --- | --- |
| `N-M` (`N--M`) | `15-17`、`12--14 hcp` | 範囲。単位が無ければ HCP。`N > M` の対は範囲ではない (シェイプの `6-5` か、未認識) |
| `N+` | `12+`、`16+ hcp` | N 以上 |
| `N` + 単位 | `20 hcp`、`3 controls` | ちょうど N |
| `at least` + 数値の族 | `at least 12 hcp`、`at least 4♠` | 下限だけを残す (上限は開く) |
| `at most` + 数値の族 | `at most 9 hcp` | 上限だけを残す (下限は 0) |
| `ca` / `about` + 数値 | `ca 10 hcp`、`about 15-17` | 近似の印を読み飛ばす (値はそのまま) |
| `LTC [N]` | `LTC 7`、`ltc` | ルーザー数 (古典的な LTC)。数が無ければ範囲なし |
| `controls` / `control` (数なし) | `controls` | 認識するが制約なし |

単位の語 (数値の直後、空白 1 つを挟んでよい):

| 語 | 指標 |
| --- | --- |
| `hcp` | HCP (単位が無いときの既定) |
| `total points`、`points`、`point`、`tp` | トータルポイント (HCP + 分布点。分布点の数え方は `#+DISTPOINTS:` §6.5) |
| `controls`、`control` | コントロール (A = 2、K = 1) |
| `losers`、`loser` | ルーザー (LTC) |

上限の既定は HCP 37、ポイント 40、コントロール 12、ルーザー 24。`1-11-2017` のような 3 つ以上の `-` の連なりは範囲ではない (日付)。

`0+ hcp` は強さの表 (§5.4.7) にも `weak` として載っているが、数値の規則が先に当たるので、実際には「0 以上の HCP」(制約なし) として読まれる。

#### 5.4.2 スート長

| 書き方 | 例 | 意味 |
| --- | --- | --- |
| `N` + スート | `5♥`、`4 card suit`、`6 cards` | ちょうど N 枚 |
| `N+` + スート | `5+♠`、`6+ suit`、`4+M` | N 枚以上 |
| `N-M` + スート | `0-1♥`、`2--3♠` | N〜M 枚 |
| `N=` + スート | `4=♠` | ちょうど N 枚 |
| `at least` / `at most` + 上のどれか | `at least 4♠`、`at most 2♥` | 片側を開く |

スートの参照は §5.3。`5+ suit` は行のコールのスート。

**落とし穴**: `4 card major` や `7+ card minor` は、`4 card` (行のコールのスートにちょうど 4 枚) と未認識の `major` に分かれる (`card` が「自分のスート」の語として先に当たるため)。どちらかのメジャーの長さは `4+ major` (`4+ M`) と書く。

#### 5.4.3 支持

支持 (フィット) は、合意したスート (それが無ければ、パートナーが最後にビッドしたナチュラルなスート。パートナーのそのノードがそのスートに 3 枚以上を示すとき) の枚数である。

| 書き方 | 例 | 意味 |
| --- | --- | --- |
| `N+` + 支持の語 | `3+ support`、`4+ trumps` | N 枚以上 |
| `N=` + 支持の語、`N` + 支持の語 | `4 trumps`、`3=supp` | N 枚以上 (支持は常に下限) |
| `N-M` + 支持の語 | `3-4 support` | N 枚以上 (上限は使わない) |
| 支持の語だけ | `support`、`fit`、`raise` | 3 枚以上 |

支持の語: `support`、`supp`、`fit`、`raise`、`trumps`。合意したスートもパートナーのスートも無ければ前提扱い (`AssumedContext`) で制約にならない。支持の断片は、ノードの `agreed_suit` を設定する。

#### 5.4.4 シェイプ

シェイプの桁は **S H D C の順** である (上流の慣例)。

| 書き方 | 例 | 意味 |
| --- | --- | --- |
| 4 桁 | `4414`、`5332` | そのとおりの分布。4 桁が全て数字なら合計が 13 でなければならない (13 でなければシェイプでない) |
| `x` を含む 4 桁 | `44xx`、`x5x5` | `x` の位置は任意 |
| `( )` の組 | `(4432)`、`54(31)`、`(54)(xx)`、`(5431)` | 括弧の中の桁は、その位置の間で入れ替えてよい。`(4432)` は 4432 型の全て、`54(31)` は ♠5 ♥4 で ♦♣ が 3-1 か 1-3 |
| 2 スート + 群 | `5-5 minors`、`5-4 majors`、`5+4+ red suits`、`55MM`、`4+4+ mm`、`5-5 ♦+♣` | 群の 2 スートに、書いた枚数 (どちらのスートにどちらでも)。`+` の無い数字はちょうど |
| `both` + 群 | `both majors`、`both MM`、`both minors` | 群の 2 スートに 4 枚以上ずつ |
| 裸の 2 数 | `6-5`、`5-5`、`6-4` | 最長のスートが a 枚以上、2 番目が b 枚以上 (a ≥ 4、a ≥ b、a + b ≤ 13)。後ろに単位やスートがあれば数値の族になる (`5-5 hcp`) |

群の語: `red suits`、`black suits`、`majors`、`major`、`minors`、`minor`、`red`、`black`、`MM` (メジャーの 2 スート、大文字小文字を区別)、`mm` (マイナーの 2 スート)、スート記号の対 `♦+♣`。`both` の後にも同じ群を書く。

注意:

- `5-5 minors` は **ちょうど** 5-5 である。5 枚以上なら `5+5+ minors` と書く。
- 括弧 1 組だけの 2 桁 (`(54)`) はシェイプにならない (4 位置に満たない)。
- 行頭の `(5431)` は列挙の印として読まれる (§5.2)。

#### 5.4.5 スート長の比較

`<スート> <演算子> <スート>` (空白は任意): `♠>=♥`、`!h > !s`、`M>oM` (束縛で置換された後)。2 つの違うスートに限る。

| 演算子 | 意味 |
| --- | --- |
| `>=` | 左のスートが右以上の枚数 |
| `<=` | 以下 |
| `>` | より長い |
| `<` | より短い |
| `=` | 同じ枚数 |

#### 5.4.7 強さ (文脈に依る)

強さの語は、行の文脈から HCP の範囲に解決される。式の記号は §5.5 と §6.5 の `#+STRENGTH:` を参照 (`gf` = 25、`inv` = 22-24、`slam` = 31、`strong` = 16、`weak` = 9、`neg` = 7、`opening` = 12、`max` = 37 が既定)。`p_min`/`p_max` はパートナーの既知の HCP の範囲 (§5.5) の下限と上限。

| 語 | 種類 | HCP の範囲 |
| --- | --- | --- |
| `forcing to game`、`game forcing`、`gameforcing`、`game force`、`any game force`、`gf`、`fg` | GF | `gf - p_min` 以上。フラグ `Forcing::ToGame` も付く |
| `invitational`、`inv`、`game try`、`g/t` | INV | `inv.start - p_min` 〜 `inv.end - p_min` |
| `limit`、`lim` | LIM | INV と同じ |
| `invitational plus`、`inv+` | INV+ | `inv.start - p_min` 以上 |
| `mildly invitational` | INV (弱め) | INV の両端から 1 を引く |
| `strongly invitational` | INV (強め) | INV の両端に 1 を足す |
| `at most invitational` | INV 以下 | 0 〜 `inv.end - p_min` |
| `minimum`、`min` | MIN | 自分の既知の範囲の下半分 (§5.5) |
| `maximum`、`max` | MAX | 自分の既知の範囲の上半分 |
| `very light`、`light`、`weak`、`wk` | 弱い | 役割とレベルによる (下の表) |
| `strong`、`str` | STR | `strong` 以上 |
| `preemptive`、`barrage`、`pre` | PRE | `#+NATURAL:` のプリエンプトの表のそのレベルの範囲 (既定 3 のレベル 5-9、4 のレベル 5-10、5 のレベル 5-11)。無ければ 0-`weak` (前提扱い) |
| `slam interest`、`slam try`、`s/t` | S/T | `slam - p_max` 以上 |
| `quantitative`、`quant` | QUANT | `(slam + 2) - p_max` 〜 `(slam + 2) - p_min - 1` |
| `negative`、`neg` | NEG | 0 〜 `neg` |
| `0+ hcp` | 弱い | (数値の規則が先に当たるので、実際には使われない) |

`weak` の範囲:

| 役割 | 範囲 |
| --- | --- |
| レスポンダー | 0 〜 `weak` (既定 0-9) |
| オープナーの 2 のレベル | ウィークツーの範囲 (既定 5-10) |
| オープナーの 3・4 のレベル | PRE と同じ |
| オーバーコーラー | ジャンプオーバーコールの範囲 (既定 5-10) |
| その他 | 0 〜 `weak` (前提扱い) |

MIN / MAX: 自分の既知の範囲 `lo..hi` を `mid = lo + (hi - lo) / 2` で割り、MIN は `lo..mid`、MAX は `mid+1..hi`。自分の範囲がまだ無いとき、オープナーは MIN = `opening` 〜 `opening + 2`、MAX = `opening + 3` 〜 21 (前提扱い)、それ以外の役割は制約なし (前提扱い)。

| 行 | 結果 |
| --- | --- |

| `1C-1H = INV` (1C = 12-21) | 10-12 |
| `1C-1H = weak` | 0-9 |
| `2S = weak, 6+!s` (オープナー) | 5-10 |
| `2S = PRE` (オープナーの 2 のレベル。プリエンプトの表に 2 は無い) | 0-9 (前提扱い) |
| `1N-2C-2H-` の後のレスポンダーの `S/T` (1N = 15-17) | 14+ |
| `1N-4N = QUANT` (1N = 15-17) | 16-17 |
| `1C-1H-1N = MIN` (1C = 12-21) | 12-16 |
| `2C-2D-2N = MIN, bal` (2C = 22+) | 22-29 |

#### 5.4.8 フォーシング

フォーシングの語は制約を作らず、ノードの `forcing` フラグだけを決める。

| 語 | フラグ |
| --- | --- |
| `non forcing`、`nonforcing`、`nf` | `NonForcing` |
| `f2nt`、`f1r`、`f1`、`forcing`、`f` | `OneRound` |
| (強さの語 GF) | `ToGame` |

- 否定した語 (`not forcing`、`non-forcing`) は `NonForcing`。
- AND の中では最も強いものが、OR の枝の間では全ての枝が一致するものだけが残る (`weak or GF` はフォーシングが不明)。可能性のヘッジ (`may be forcing`) は何も言わない。
- 語が無ければ `Unknown`。

#### 5.4.9 スプリンター

| 語 | 意味 |
| --- | --- |
| `splinter`、`spl` | 短いスート 0-1 枚 ∧ 合意したスートに `#+CONVENTION: splinter=N` 枚以上 (既定 4) ∧ GF の強さ |
| `mini-splinter`、`mini splinter` | 同じく、強さは INV |

- 語の後にスートを書くと、それが短いスート (`SPL ♣`、`splinter m`)。書かなければ行のコールのスート。
- 合意したスートは §5.4.3 の支持と同じ規則で決める。
- 説明文に明示した要素が優先する: HCP/ポイントがあれば強さの部分を、短さ (`singleton` など) があれば短いスートの部分を、合意したスートの長さがあれば支持の部分を捨てる。
- スプリンターは `artificial` を立てる。

#### 5.4.10 慣習

次の語は **制約を作らない**。ノードに `artificial` を立てるだけである (否定されたもの、可能性のヘッジが付いたものを除く)。制約は数値やシェイプで別に書く (`!TRF, 5+♥`)。

`artificial`、`art`、`relay`、`(r)`、`asking for`、`asks`、`asking`、`ask`、`puppet to`、`puppet`、`pup`、`pass/correct`、`pass / correct`、`p/c`、`t/o`、`forced`、`choice of games`、`cog`、`cuebid`、`cue`、`waiting`、`transfer to`、`transfer`、`retransfer`、`trf`、`garbage stayman`、`muppet stayman`、`puppet stayman`、`garbage stay`、`muppet stay`、`stayman`、`stay`、`smolen`、`landy`、`michaels`、`unusual nt`、`unusual`、`unt`、`gambling`、`lebensohl`、`ogust`、`bw`、`rkcb`、`kcb`、`k/b`、`multi-coloured`、`multi-colored`、`multi`、`sign off`、`sign-off`、`s/o`、`to play`、`t/p`

- `sign off`、`sign-off`、`s/o`、`to play`、`t/p` は、さらに `sign_off` フラグを立てる。
- `transfer`/`trf` は移動先のスートを記録しない (`NodeFlags.transfer_to` は常に `None`)。
- 慣習名は `artificial` を立てるので、ナチュラルな意味の行に `to play` を書くとその行も人工的扱いになる (付録 B)。

#### 5.4.11 スートの質

スートの質は、行のコールのスート (「自分のスート」) のカードの要件になる。コールがスートのビッドでなければ前提扱いで制約にならない。枚数は加えない。

| 語 | 意味 |
| --- | --- |
| `with stopper`、`stopper in`、`stoppers`、`stopper`、`stop` | 指定のスートに A、K + 1 枚以上、Q + 2 枚以上、J + 3 枚以上のどれか |

| --- | --- |

#### 5.4.14 ナチュラル

`natural`、`nat`: 行のコールのナチュラルな意味。

- NT のビッド: バランス (`#+BALANCED:` の型)。
- スートのビッド: そのスートの最小枚数 (役割とレベルによる。`#+NATURAL:` §6.5)。オープナーの 1 のレベルはメジャー 5 (`1M=`)、マイナー 3 (`1m=`)、オープナーのそれ以外は 5、レスポンダーの 1 のレベルは 4、それ以上は 5、オーバーコーラーの 1 のレベルは 5、2 のレベルは 5、ジャンプは 6、アドバンサーは 5、バランサーは 5。
- パス、ダブル、リダブル: 制約なし。
- 同じスートの長さを明示していれば、NAT の長さは捨てる。

#### 5.4.15 範囲なし

次の語は認識するが制約を作らない (「範囲を狭めない」ことを明示する語)。

### 5.5 文脈

文脈に依る語は、行の **経路** から次の情報を得て解決する。

| 情報 | 由来 |
| --- | --- |
| 役割 | オープナー (我々が開いた側で最初にビッドした人)、レスポンダー (その相方)、オーバーコーラー (相手が開いた後、我々の最初のビッド)、アドバンサー (その相方)、バランサー (パス・パスの後の再開) |
| コールのレベルとジャンプかどうか | 行のコール |
| パートナーの既知の HCP の範囲 | 経路の上のパートナーのノードの制約。何も言っていなければ `opening` 〜 21 と仮定 (前提扱い) |
| 自分の既知の HCP の範囲 | 経路の上の自分の前のノードの制約 |
| 合意したスート | 支持の断片を含む経路上のノード、またはパートナーのスートの繰り返し |
| `#` のスート | §5.2 |
| 相手の最後のビッドのスート | ストッパーの既定 |

**前提扱い** (`AssumedContext` (Info)): 解決に必要な文脈が無く、既定値を仮定したとき (パートナーの範囲が不明な GF など)、またはスートが決まらず制約にできなかったとき。前提扱いの強さの語は、同じ説明文の中の前提扱いでない強さの語と重ならなければ捨てる (OR の下の語を除く)。

**明示が勝つ**。文脈から出した値と、同じ説明文で明示した値がぶつかるときは明示が勝つ。

- 強さの語 (`GF`、`INV`、`weak`、…) の HCP は、HCP/ポイントの断片がその語と **AND で並んでいる** (否定も可能性のヘッジも無い) とき捨てる。`INV, 7-9 hcp` は 7-9。`GF, not 20+ hcp` は GF のまま (否定は明示の値ではない)。`weak or 16+` は weak のまま (別の枝)。
- `QUANT` があると、同じ説明文の `INV` 系の語の HCP を捨てる (`QUANT INV to 6NT`)。
- `MIN`/`MAX` は、AND で並ぶ weak/PRE/NEG/STR の範囲を基準にして半分に割る (`weak, MAX` は weak の範囲の上半分)。
- NAT の長さは、同じスートの長さの明示で捨てる (§5.4.14)。スプリンターの各部分も同様 (§5.4.9)。

### 5.6 組み立てとフラグ

- 可能性のヘッジの付いた断片はリテラルを出さない。否定は `Not`。AND の中の「範囲なし」は消え、OR の枝の 1 つが範囲なしなら OR 全体が範囲なし。
- 結果は、リテラルが 8 個以下なら DNF (選言標準形) に単純化する。DNF が大きすぎて切り詰めたときは `DnfTruncated` (Warning)。
- 空の説明文は制約なし (`EmptyDescription` (Info))。

| フラグ | 立つ条件 |
| --- | --- |
| `artificial` | アラート印 `!`、慣習の語 (§5.4.10)、スプリンター |
| `forcing` | フォーシングの語と GF (§5.4.8) |
| `soft` | ヘッジが 1 つでもある |
| `agreed_suit` | 支持の断片があり、合意したスートが分かるとき |
| `sign_off` | `sign off`、`s/o`、`to play`、`t/p` など |
| `stop` | `{stop}` (§6.3) |
| `transfer_to` | 常に `None` (未実装) |

### 5.7 認識率

各行について、認識した断片の文字数の割合 `ratio = 認識した文字数 / (全体 - 未認識のストップワード)` を計る (空の説明文は 1.0)。

- 未認識の断片ごとに `UnrecognizedFragment` (Info)。
- 行の (展開のうち最良の) 認識率が `#+RECOGNITION:` (既定 0.5) を下回ると `LowRecognition`。その行が他に制約を持つ (一部は認識された) なら Warning、全く制約を持たないなら Info。
- 認識されなかった文は制約にならないだけで、害は無い。ただし制約の無いノードは「どんな手でも」になり、兄弟の選択 (§7.4) で思わぬ手を拾う。重要な行は認識される語で書く。

```bml
1N = 15--17 hcp, bal

1N-
2C = !STAY, 8+ hcp, 4+ major
2D = !TRF, 5+!h
2H = !TRF, 5+!s
2N = INV, bal, 0--3!h, 0--3!s
3N = 10--15 hcp, to play
4N = QUANT, bal
  P = MIN
  6N = MAX
```

```bml
1H = 12--21 hcp, 5+!h

1H-
3S = !SPL, singleton !s, 4+!h, 13--16 hcp
2N = !Jacoby, GF, 4+ support
3H = LIM, 4+ support
4H = PRE, 5+ support, 0--9 hcp
```

`3S` は `2N` の部分集合なので、`2N` より先に書く (Exact 行どうしはファイル順に試される §7.4)。逆に書くと `SiblingSubset` と `ShadowedBranch` (Warning) が出る。

```bml
1C = 12--21 hcp, 3+!c

1C-
1H = 6+ hcp, 4+!h, !h>!s
1S = 6+ hcp, 4+!s, !s>=!h
```

```bml
2N = 20--21 hcp, bal
3C = PRE, 7+!c, 2 of top 3
4S = PRE, 8+!s, AKQxxxxx
1D = 12--21 hcp, 4+!d, unbalanced

1D-
1N = 6--10 hcp, usually bal, may have 4!h
```

## 6. 注釈とメタ行

### 6.1 `{prio:N}` (優先度)

- 説明文のどこかに書く。`N` は −32768〜32767 の整数 (`{prio:-100}`、`{prio:5}`)。既定は 0。
- 同じ位置の候補 (兄弟) の順位は、**優先度の大きい順**、同じなら `#+TIEBREAK:` (既定は展開の順: Exact 行、次にパターン行)、それでも同じならコールの順 (§7.4)。パターン行を Exact 行より上位にしたいときは `{prio:N}` を使う。
- 典型は、どんな手でも当てはまる受け皿の行を最下位にする `P = {prio:-100} any hand`。
- 優先度の違う兄弟の包含は `SiblingSubset` が Info になる (意図した順位付けとみなす)。

### 6.2 `{w:X}` (枝の重み)

- 説明文が最上位で OR (列挙 `a) b)` や `or`) のとき、各枝の事前の重みを書く: `{w:2} {w:1}` は 1 つ目の枝を 2 倍。`X` は実数。書いた数が枝の数と一致したときだけ使う (一致しなければ等分)。
- 使うのは解釈の旧方式 (`InterpretMode::Legacy`) だけである。既定の `InterpretMode::Mirror` は重みを読まない。
- OR でない行に書いても Lint は出ない (付録 B)。

```bml
1D = {w:3} {w:1} one of:
     a) 12--21 hcp, 4+!d
     b) 12--14 hcp, 4432
```

### 6.3 `{stop}` (システム停止)

- 説明文のどこかに書く (`{ stop }` も可。`{stopper}` は該当しない)。**その行の後** にシステム停止を置く (§7.7)。行自体は普通の行としてコンパイルする。
- 典型は `P = {prio:-100} {stop} any hand`: 「他のどの行にも当てはまらなければパスし、以後パートナーシップは (他に書いた行が無い限り) パスし続ける」。
- `#STOP` (§2.10) は、行を足さずに停止だけを置く。

### 6.4 `#+KEY:` の構文

```ebnf
metapara = metaline , { NL , metaline } ;
metaline = WS0 , "#+" , KEY , ":" , VALUE ;
KEY      = ( ALNUM | "_" ) , { CHAR - ":" } ;   (* trimmed *)
VALUE    = { CHAR } ;                           (* everything after the first ":", trimmed *)
```

- キーは大文字小文字を問わない (`#+title:` と `#+TITLE:` は同じ)。
- **最初の定義が勝つ**。同じキーの 2 回目以降は黙って無視する (`#INCLUDE` で読んだ共通ファイルの値を、ルートファイルの先頭で上書きできる)。
- 値の書式が読めないと `UnknownDirective` (Warning) を出し、その部分は既定値のまま。`key=value` の並びのキーは、1 つずつ独立に読む (1 つが読めなくても他は効く)。
- 未知のキーは `SystemMeta::extra` に文字列のまま残る (上流の `#+AUTHOR` 以外の任意のキーと同じ)。
- 値の中の `key=value` の副キーは **大文字小文字を区別する** (`gf=26` は可、`GF=26` は読めない)。

## 7. 解決の意味論 (著者から見た動作)

本節は、コンパイルしたシステムが実際のオークションでどう使われるか (`bridge-bidding` の `choose_bid`) を、書き手が知るべき範囲でまとめる。

### 7.1 トライと照合

- 全ての表は 1 つの **トライ** (オークションの接頭辞の木) にまとめられる。根は 2 つあり、我々が開いたオークションと相手が開いたオークションである。先頭のパスは経路から除き、オープナーの位置は席の条件として扱う (§2.6)。
- トライの辺は、具体的なコール (`1H`、`(2S)`、`P`) か、相手の類のワイルドカード (`(any)`、`(bid)`、`(suit)`) である。各ノードには (席の条件、バルの条件、ノード) のエントリが並ぶ。
- 実際のオークションの照合は、接頭辞を先頭から 1 コールずつたどる。
  1. **具体的な辺を先に** 試す。無ければ、ワイルドカードの辺を **入れた順に** 試し、コールがその類に当てはまる最初のものをたどる。
  2. **後戻りしない**。具体的な辺をたどった先で行き詰まっても、ワイルドカードの辺を試し直さない。
  3. たどった先のノードのエントリから、実際のオープナーの位置とバルに当てはまる最も具体的なもの (§4.8) を選ぶ。我々の側のノードでどのエントリも当てはまらなければ、照合はそこで止まる。
- **完全一致** (接頭辞の全てのコールをたどれた) なら、その位置の子が候補になる。完全一致しなければ、相手のコールを最大 2 つまでパスに置き換えて照合し直す (`resolve_lenient`。置き換えの少ない一致を優先)。つまり **表の無い相手の割り込みは、パスとして扱われることがある**。これを避けるには、割り込みの表 (`(any)` など) を書く。

### 7.2 候補の選び方

`choose_bid` (手 + オークション → コール) は次のとおり動く。

1. 照合で得た位置の子 (我々のコールの行) を候補にする。
2. 合法でない候補 (不十分なビッド、できないダブル) を除く。手が制約を満たさない候補を除く。
3. 合法な候補が 1 つも無い位置 (**システム外**) では、自然推論 (`NaturalInference`) の候補 (ナチュラルな意味とレベルの床 `LevelFloor` による強さの下限) を使う (§7.8)。
4. 呼び出し側が `ImplicitPass::Complement` を選んでいて、完全一致の位置で、パスの行が無く、合法な候補があるとき、**暗黙のパス** を足す (優先度は最下位 `i16::MIN + 1`、制約は兄弟の和の補集合)。既定の `ImplicitPass::Never` では足さない (どの候補も満たさなければ `NoCandidate`)。
5. 残った候補を順位 (§7.4) で並べ、先頭を選ぶ。

### 7.3 完全一致、部分一致、ナチュラル

| 状況 | 候補 | 由来 (`ChoiceSource`) |
| --- | --- | --- |
| 完全一致で、合法な子がある | 子 (+ 暗黙のパス) | `System` (`ImplicitPass`) |
| 相手のコールをパスに置き換えて一致 (部分一致) | その位置の子。暗黙のパスは足さない | `System` |
| 合法な子が無い (システム外) | 自然推論の候補。当てはまらなければ `Complement` のときパス | `Natural` (`ImplicitPass`) |

### 7.4 順位 (`rank_cmp`)

同じ位置の候補は、次の順に比べる (前が上位)。

1. 優先度 `{prio:N}` の大きい方 (既定 0)。
2. `#+TIEBREAK:` の規則。既定の `row-order` は **行が展開された順** で、兄弟の間では「Exact 行 (ファイル順)、次にパターン行 (ファイル順)」になる (§4.8 の規則 1)。したがって `2M` のようなパターン行は、ファイル上で先に書いても、同じ位置の Exact 行 (`1N`、`P`、`D`) より下位である。表をまたぐ兄弟 (別の表が同じ位置に足した行) は、先に展開された表の行が上位。
3. コールの順 (低いコールが先。パス、ダブル、リダブルはビッドより先)。

上位の候補が手に当てはまれば下位は選ばれない。したがって、ある候補が実際に選ばれる手の集合は「自分の制約 − 上位の兄弟の制約の和」である (**排他領域**)。`ExclusiveIndex` はこれを前もって計算し、次の Lint を出す。

- `ShadowedBranch` (Warning): 我々の行の (最上位の OR の) 枝が、全ての条件の組で上位の兄弟に覆われていて選ばれない。相手の行には出ない。
- `OverlappingBranches` (Info): 1 つの行の OR の枝どうしが重なる (索引は重なりを分ける)。
- 兄弟の制約どうしの包含と重なりは `SiblingSubset` (Warning。優先度が違えば Info)、`SiblingOverlap` (Info)。相手の行どうしにも出る。見出しの相手のコール (履歴行の `(2H)` など) が説明を持たないと、同じ位置の相手の見出しどうしが互いを含んで `SiblingSubset` になる。相手のコールにも説明を書く (`1S-(2H)- = 5+!h`) か、Warning として無視する。

**書き方の指針**: 狭い行を先に、広い行を後に書く。受け皿は `{prio:-100}` で最下位にする。

### 7.5 暗黙のパス

- 経路の上の暗黙のパス (§3.5) と、選択の暗黙のパス (§7.2 の 4) は別物である。
- 選択の暗黙のパスは呼び出し側の選択 (`ImplicitPass`) で、BML からは制御できない。パスを確実に候補にしたいときは、パスの行を書く (`P = {prio:-100} any hand`)。

### 7.6 相手のコール

- 我々の手番の候補は、直前の相手のコールまで一致した位置の子である。相手の割り込みの表が無ければ、§7.1 の部分一致で「相手がパスした」位置の子が候補になる (合法なものだけ)。
- 具体的な割り込みの表は類の表に勝つ。類の表どうしは、先に入れた (ファイルで先の) 表の類が勝つ。`1S-(bid)-` の表が `1S-(any)-` より先にあれば、相手のビッドは `(bid)` の表へ、パスとダブルは `(any)` の表へ行く。
- 相手のコールのノードの制約 (見出しに書いた説明) は、相手の手の推論 (`interpret`) に使われる。

### 7.7 システム停止

**意味**。位置 S の停止は、S の下に次の行を **際限なく**、**全ての表の後に** (表の `#SEAT`/`#VUL` の条件で) 書いたのと同じである。

```text
(any)
  P = {prio:-100} any hand
    (any)
      P = {prio:-100} any hand
        ...
```

S の次の手番が我々なら `P` から始まる。つまり S からは相手の任意のコールと我々のパスが交互に続き、我々の手番では「どんな手でもパス」が優先度 −100 の最下位の候補として必ず出る。

- **書き方**: 行の `{stop}` (その行の後)、行の子の位置の `#STOP` (その行の後)、表の最上位の `#STOP` (表の履歴の後)。停止の位置のノードには `NodeFlags::stop` が立つ (情報用)。
- **「どんな手でもパス、−100」の意味**: 停止のパスは候補を 1 つ足すだけである。同じ位置に書いた行があれば、それらが上位の候補として先に試され、当てはまる手はその行を選ぶ。どれにも当てはまらない手だけがパスする。
- **書いた行が勝つ**: 「全ての表の後」なので、ファイル上の順序にかかわらず、表が書いた行とワイルドカードの辺が停止に優先する。
  - S の後の相手の具体的なコールの表 (`1C-1N-(2S)-`) があれば、その辺をたどり、停止のパスは出ない (その表の行だけが候補)。
  - S で表が書いた `(bid)`/`(suit)` の辺は、停止の `(any)` より先に試される。後戻りしないので、停止はその辺の下には続かない (そこでも止めたいなら、その表にも `#STOP` を書く)。
  - 停止のたどる位置に表が書いた我々のパスの行は、その優先度と説明を保つ。説明が空のプレースホルダだけを停止のパスで埋める (`DuplicatePath` (Info))。
- **停止の後の我々のパス以外のコール**: それは行ではないので、照合はその手前で止まり、以後はシステム外 (自然推論) になる。
- **`StopUnderForcing` (Warning)**: パートナーのフォーシングのコール (相手はパス) の後、または我々のゲームフォーシングがゲームに届く前に、停止のパスが (上位の行に覆われずに) 候補になる。手によってはフォーシングをパスしてしまうので、停止の位置を見直す。
- 停止は内部では合成ノードの対と共有の輪で表す (ノード数はほぼ増えない)。詳細は `06-system.md` §4.5。

```bml
1N = 15--17 hcp, bal

1N-
2C = !STAY, 8+ hcp, 4+ major
3N = 10--15 hcp, to play
  #STOP
P = {prio:-100} {stop} 0--7 hcp

1N-2C-
2D = no 4 card major
2H = 4+!h
2S = 4+!s
```

この例では、`1N-P` の後 (相手が何をしても) と `1N-3N` の後、我々はパスし続ける。`1N-2C-` の後に停止は無いので、表の無い位置はシステム外になる。

### 7.8 システム外と自然推論

- 合法な候補が 1 つも無い位置では、自然推論 (`NaturalInference`) が候補を出す。自然推論は `#+NATURAL:` の値 (呼び出し側が渡した場合) と、コールのナチュラルな意味 (新しいスートは長さ、NT はバランス、レベルに応じた強さの床 `LevelFloor`) で候補を作る。
- システム外になる典型: 表の無い位置 (停止の無い位置で相手が割り込んだ後で部分一致もしないとき)、停止の後に我々がパス以外をした後、履歴の最後のコールの下に行が無い位置。
- システムの穴を自然推論に任せたくなければ、表を書くか停止を置く。

## 9. 完全な EBNF

字句の約束: `NL` は改行、`SP` は半角スペース 1 個、`WS` は `SP` の 1 個以上の並び、`WS0` は 0 個以上、`CHAR` は改行以外の任意の文字、`BLANK` は空白だけの行。字句は大文字小文字を区別する (区別しないものは注記)。

### 9.1 ファイルと段落

```ebnf
(* after #INCLUDE expansion and removal of column-0 comments *)
file        = { BLANK , NL } , [ paragraph , { BLANK , NL , { BLANK , NL } , paragraph } ] ;
paragraph   = line , { NL , line } ;               (* no blank line inside *)

(* preprocessing, per physical line, before paragraphs are formed *)
comment     = "//" , { CHAR } ;                     (* only at column 0; the line is dropped *)
include     = WS0 , "#" , WS0 , "INCLUDE" , WS0 , PATH , [ WS , { CHAR } ] ;
PATH        = CHAR - SP , { CHAR - SP } ;           (* relative to the including file *)

(* a paragraph's kind is decided by its first line, in this order *)
paragraph   = heading | list | vulpara | seatpara | enumeration
            | bidtable | metapara | directivetable | prose ;
heading     = WS0 , "*" , { CHAR } , { NL , line } ;
list        = WS0 , "-" , { CHAR } , { NL , line } ;
vulpara     = WS0 , "#VUL" , WS , TRI , TRI , WS0 , { NL , line } ;
seatpara    = WS0 , "#SEAT" , WS , SEAT , WS0 , { NL , line } ;
enumeration = WS0 , DIGIT , { DIGIT } , "." , ( SP | NL ) , { CHAR } , { NL , line } ;
bidtable    = { directive , NL } , firstrow , { NL , ( row | directive | contline ) } ;
metapara    = metaline , { NL , metaline } ;
directivetable = directive , { NL , ( directive | row | contline ) } ;   (* a table starting with "#..." *)
prose       = line , { NL , line } ;

TRI         = "Y" | "N" | "0" ;
SEAT        = "0" | "1" | "2" | "3" | "4" | "12" | "34" ;
metaline    = WS0 , "#+" , KEY , ":" , VALUE ;
KEY         = ( ALNUM | "_" ) , { CHAR - ":" } ;     (* case-insensitive, trimmed *)
VALUE       = { CHAR } ;                             (* trimmed *)
```

### 9.2 ビディング表

```ebnf
firstrow    = historyrow | row ;
historyrow  = INDENT , seq , [ WS , [ "=" , WS0 ] , description ] ;
row         = INDENT , calltok , [ WS , [ "=" , WS0 ] , description ] ;
contline    = DESCCOL , { CHAR } ;       (* indent equal to the previous row's description column *)
INDENT      = { SP } ;                   (* spaces only; the table's unit is its first parent-child step *)
seq         = calltok , { ( "-" | ";" ) , calltok } , { "-" | ";" } ;   (* contains at least one "-" or ";" *)

directive   = WS0 , ( "#HIDE" | "#BIDTABLE" | "#STOP" | "#ANYORDER"
                    | "#COPY" , WS , NAME | "#ENDCOPY"
                    | "#CUT" , WS , NAME | "#ENDCUT"
                    | "#PASTE" , WS , NAME , { WS , SUBST } ) , WS0 ;
NAME        = CHAR - SP , { CHAR - SP } ;
SUBST       = TARGET , "=" , REPLACEMENT ;      (* plain text replacement, applied in order *)
TARGET      = CHAR - ( SP | "=" ) , { CHAR - ( SP | "=" ) } ;
REPLACEMENT = { CHAR - SP } ;
```

### 9.3 コールトークン

```ebnf
calltok     = "(" , callcore , ")"                 (* opponents *)
            | callcore ;                           (* us *)
callcore    = atom , { "/" , ( atom | strainspec ) } ;   (* a bare strainspec reuses the last level *)
atom        = "XX" | "X" | "P" | "D" | "R"
            | oppclass
            | DIGIT , { DIGIT } , stepword
            | level , strainspec ;
oppclass    = "any" | "suit" | "bid" ;
stepword    = "step" | "steps" ;                   (* case-insensitive *)
level       = "1" | "2" | "3" | "4" | "5" | "6" | "7"
            | "n"                                  (* every sufficient level *)
            | "c"                                  (* cheapest sufficient *)
            | "j" ;                                (* one above the cheapest *)
strainspec  = redblack | variable | literal ;
redblack    = "red" | "black" ;                    (* case-insensitive *)
variable    = "oM" | "om" | "M" | "m" | "X" | "x" | "Y" | "y" | "Z" | "z" ;
literal     = "NT" | "N" | suit , { suit } ;
suit        = "C" | "D" | "H" | "S" ;
```

### 10.2 競り合いのクックブック

各項目は独立したファイルとしてコンパイルできる。自分のシステムには、履歴と行だけを写せばよい。

**C-1. 同じ応答を 2 つの位置に貼る (`#PASTE` の置換)**。1NT と 2NT の後のトランスファーを 1 つのクリップボードで書く。置換の印はコールトークン用 (`\L` はレベル) と説明文用に分ける。

```bml
#CUT transfers
\L\R = !TRF, 5+\M
  \L\S = 2+\M
#ENDCUT

1N = 15--17 hcp, bal
2N = 20--21 hcp, bal

1N-
#PASTE transfers \L=2 \R=D \S=H \M=!h
#PASTE transfers \L=2 \R=H \S=S \M=!s

2N-
#PASTE transfers \L=3 \R=D \S=H \M=!h
#PASTE transfers \L=3 \R=H \S=S \M=!s
```

注意: 置換は書いた順に単純な文字列置換で行う。`\M=!h` の後に `\M` を含む別の印 (`\MM` など) を置き換えることはできないので、印は互いに接頭辞にならない名前にする。

**C-2. 相手のオープニングへのオーバーコール (`(1X)`、`c`/`j`)**。`X` は相手のスート、`Y` は我々の新しいスート。`cY` は最も安いレベル、`jY` はジャンプオーバーコール。

```bml
(1X)- = 11+ hcp, 3+X
#ANYORDER
cY = 8--16 hcp, 5+Y
jY = weak, 6+Y
1N = 15--18 hcp, bal, stopper
D = t/o, 12+ hcp
2N = !Unusual, 5+5+ minors
P = {prio:-100} {stop} any hand
```

`#ANYORDER` で `Y` は X より低いスートにもなる (1S の後の 2H、1H の後の 2C)。`cY` は相手のスートより低いスートでは 2 のレベルになる。`!Unusual` の `U` を大文字にしているのは、`!u` 以外でも小文字の `!c`/`!d`/`!h`/`!s` で始まる語 (`!cue`、`!strong`) がスート記号に読まれるのを避ける習慣である (§3.6)。

**C-3. アドバンス (`(1X)-1Y-(P)-`)**。オーバーコールの後、パートナーの応答。

```bml
(1X)- = 11+ hcp, 3+X
1Y = 8--16 hcp, 5+Y

(1X)-1Y-(P)-
2Y = 6--10 hcp, 3+Y
cX = !Cue, 11+ hcp, 3+Y
3Y = PRE, 4+Y, 0--9 hcp
1N = 8--11 hcp, stopper
P = {prio:-100} {stop} 0--5 hcp
```

最初の表はオーバーコールそのものの定義 (と相手のオープニングの説明) で、2 つ目の表の履歴はそれを辿る。履歴行に説明を書くと、それは最後のコール (ここでは相手の `(P)`) の説明になるので、オーバーコールの説明は別の表に書く (§3.4)。`(1X)` の X と `1Y` の Y は履歴で束縛され、`cX` は相手のスートのキュービッド (最も安いレベル) になる。`1Y` が `1X` より高いスートのときだけ、つまり X < Y のときだけ展開される (履歴に `#ANYORDER` は効かない。表全体に効かせたければ `#ANYORDER` を書く)。

**C-4. バランシング (`(1X)-P-(P)-`)**。

```bml
(1X)- = 11+ hcp, 3+X
P = {prio:-100} any hand

(1X)-P-(P)-
1N = 11--14 hcp, bal, stopper
cY = 7--12 hcp, 5+Y
D = t/o, 8+ hcp
P = {prio:-100} {stop} any hand
```

`1N` は相手のスートが 1C〜1S のときだけ十分である。1S の後の `1N` は十分、2 のレベルの `(nX)` の表なら `IllegalCall` になるので、2 のレベルのバランシングは別の表に書く。

**C-5. ネガティブダブル (`1m-(1M)-`)**。

```bml
1m = 12--21 hcp, 3+m

1m-(1M)- = 8+ hcp, 5+M
D = !negative, 6+ hcp, 4+oM
1N = 6--10 hcp, stopper in M
2m = 6--10 hcp, 5+m
2M = !Cue, 11+ hcp, 4+m
P = {prio:-100} {stop} 0--5 hcp
```

`m` と `M` は別の変数で、`1m-(1M)-` は 1C/1D × 1H/1S の 4 つの表になる。説明文の `oM` は、相手のメジャーでない方のメジャーになる。

**C-6. 1NT への割り込み (`1N-(D)-`、`1N-(bid)-`、`1N-(2X)-`)**。

```bml
1N = 15--17 hcp, bal

1N-(D)- = 15+ hcp
XX = 10+ hcp
2C = !STAY, 5--9 hcp, 4+ major
P = {prio:-100} {stop} 0--9 hcp

1N-(2X)- = 5+X
3N = 10--15 hcp, stopper, to play
D = t/o, 8+ hcp
2N = !Lebensohl, relay, 4--7 hcp
P = {prio:-100} {stop} any hand

1N-(bid)- = 5+ card suit
D = 8+ hcp
P = {prio:-100} {stop} any hand
```

照合は具体的な辺を先に試すので、`1N-(D)` と 2 のレベルのスートのビッド (`(2C)`〜`(2S)`) はそれぞれの表へ、他のビッド (`(2N)`、`(3C)` など) は `(bid)` の表へ行く。`(bid)` の表は `(D)` を拾わない。相手のパスは `1N-` の表 (§10.1) がそのまま使われる。

**C-7. 我々のオープニングへのダブル (`1M-(D)-`)**。

```bml
1M = 12--21 hcp, 5+M

1M-(D)- = t/o, 12+ hcp
2N = !Jordan, 10+ hcp, 4+ support
XX = 10+ hcp
2M = 6--9 hcp, 3+ support
P = {prio:-100} {stop} 0--5 hcp
```

**C-8. サインオフの後で止める (`{stop}`、`#STOP`)**。

```bml
2N = 20--21 hcp, bal

2N-
3N = 4--10 hcp, to play
  #STOP
6N = 13--15 hcp, bal, to play
  #STOP
4N = QUANT, bal
  P = MIN
    #STOP
  6N = MAX
    #STOP
P = {prio:-100} {stop} 0--3 hcp
```

停止の後に相手が割り込んでも、我々は (その位置に書いた行が無ければ) パスし続ける。

**C-9. 席とバルで変わるオープニング (`#SEAT`、`#VUL`)**。

```bml
1S = 12--21 hcp, 5+!s
2S = weak, 6+!s

#SEAT 34

1S = 10--21 hcp, 5+!s

#SEAT 0

#VUL NY

2S = 4--10 hcp, 6+!s

#VUL 00
```

3 席目・4 席目の 1S は 10 HCP から、我々がノンバルで相手がバルのときの 2S は 4 HCP から。それ以外の 1S / 2S は最初の定義。

**C-10. 相手の 2 のレベル以上のオープニング (`(nX)` と相対レベル)**。

```bml
(2X)- = weak, 6+X
2N = 15--18 hcp, bal, stopper
cY = 11--16 hcp, 5+Y
D = t/o, 13+ hcp
P = {prio:-100} {stop} any hand

(3X)- = 7+X
3N = 16--21 hcp, stopper, to play
cY = 13--17 hcp, 5+Y
D = t/o, 13+ hcp, 0--2X
P = {prio:-100} {stop} any hand
```

`cY` はパターン行なので、ファイル上で先に書いても Exact 行の `D` より下位になる (§4.8、§7.4)。`(3X)-` の `D` に `0--2X` (相手のスートの短さ) を書かなければ、`cY` の手は全て `D` に覆われて選ばれない (`SiblingSubset`、`ShadowedBranch`)。

`(nX)-` と書くと 1 のレベルから 7 のレベルまで 28 の表になり (`WideWildcard`)、2 のレベルと 3 のレベルで違う行を書き分けられない。レベルごとに表を分けるのがよい。

## 11. 落とし穴

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 段落がビディング表になり、`UnknownCallToken` が出る | 地の文が `P`、`D`、`R`、`X`、`1C` のようなコールの形、あるいは `any`、`bid`、`suit` で始まる (§2.2) | 地の文の先頭の語を変える |
| 相対レベルの行が全部消える | 段落の最初の行が `cS` などの相対レベル (§4.3) | 履歴行の後か、表の 2 行目以降に置く |
| 子の行が親の説明の続きになる | 子の字下げが親の説明文の桁と同じ (§3.3) | 子の字下げを浅くする |
| タブで字下げした行が列 0 として読まれる | 字下げはスペースだけを数える (§2.1) | スペースで字下げする |
| `4 card major` が読めない | `card` が「自分のスート」として先に当たる (§5.4.2) | `4+ major`、`4+ M` と書く |
| 行頭の `(5431)` が読めない | 列挙の印として読まれる (§5.2) | 行の途中に置くか、括弧を外す |
| `stop` を「止まる」の意味で書いた | 説明文の `stop` はストッパー (§5.4.12) | `{stop}` か `#STOP` を使う |
| `5-5 minors` が 6-5 の手に当てはまらない | 群の付いた数字はちょうどの枚数 (§5.4.4) | `5+5+ minors` と書く |
| 変数の説明が置き換わらない | 説明文の変数は語の境界でだけ置換 (§5.2)。`5+Ms` は置換されない | `5+M` の後に空白か区切りを置く |
| 相手の割り込みの後に 1 つ前の表の行が出る | 表の無い割り込みは相手のパスとして照合し直す (§7.1) | 割り込みの表 (`(any)` など) か停止を書く |
| 停止の後にシステムの行が続かない | 停止の後の我々のパス以外のコールはシステム外 (§7.7) | その位置に表を書く |
| パターン行の一部のコールが出ない | 先の Exact 行の兄弟と同じコールは捨てられる (`ShadowedByExact`) | 意図どおりか確かめる |
| 同じ経路の 2 つ目の定義が効かない | 先の定義が勝つ (`DuplicatePath`) | 1 つにまとめる。席・バルで分けるなら `#SEAT`/`#VUL` |
| `!cue`、`!strong`、`!dbl` のアラートが効かず、説明が `♣ue` などになる | 小文字の `!c`/`!d`/`!h`/`!s` はスート記号 (§3.6、§5.1) | `!Cue`、`!CUE` のように 2 文字目を大文字にする |
| 履歴行の説明が思った相手に付かない | 履歴行の説明は履歴の **最後のコール** のもの (§3.4)。`(1X)-1Y-(P)- = …` は相手の `(P)` の説明 | 途中のコールの説明は、そのコールで終わる別の表に書く |
| ファイル上で先に書いたパターン行が、後の Exact 行に負ける | 兄弟は Exact 行を先に展開し、`row-order` はその順 (§4.8、§7.4) | パターン行の制約を狭めるか、`{prio:N}` で上げる |
| 相手の見出しに `SiblingSubset` (Warning) が並ぶ | 説明の無い相手のコールどうしは互いを含む (§7.4) | 相手のコールに説明を書く (`(1X)- = 11+ hcp, 3+X`) |
